1. INTRODUCTION
--------------------------------------------------------------------------------
The cinema and entertainment industry has witnessed a paradigm shift from manual,
physical box-office ticketing to sophisticated digital reservation ecosystems.
Modern moviegoers expect instantaneous booking confirmation, interactive auditorium
seat selection, and responsive interfaces across devices. Simultaneously, cinema
operators require centralized administration tools to catalog movies, manage screening
schedules, set differential pricing (e.g., Regular vs. VIP seats), monitor live
financial metrics, and manage user accounts securely.

"CineMagic" is an end-to-end, enterprise-grade hybrid movie ticket booking and
cinema management platform. The system couples a robust, high-performance Spring
Boot RESTful backend with two specialized clients:
1. An integrated, responsive Admin Web Dashboard served directly by the backend for
   operational and administrative control.
2. A modern, desktop-native Java Swing Client application styled with the FlatLaf
   Light design language, optimized for high responsiveness, maximized viewing,
   and visual seat selection.

The architecture emphasizes low latency, transactional integrity, multi-tiered
caching (RAM, disk, and server-side), and seamless environment portability via
externalized configuration files.


2. ABSTRACT
--------------------------------------------------------------------------------
The CineMagic Movie Ticket Booking System addresses the challenges of scalability,
image delivery latency, and transactional seat contention in cinema reservation
workflows. Built upon Java 21 and the Spring Boot framework, the backend exposes
a stateless REST API authenticated via JSON Web Tokens (JWT) and backed by a MySQL
relational database. Uniquely, movie poster imagery is stored natively as binary
data (LONGBLOB) within MySQL, eliminating dependencies on external file servers
or cloud object storage while leveraging Spring Cache and Caffeine in-memory
caching with HTTP ETag validation to ensure sub-millisecond retrieval.

For cinema administration, a web-based management portal provides real-time business
intelligence metrics, CRUD operations for movie titles, binary poster uploads,
showtime scheduling, ticket auditing, and user management (including deletion).
For end users, a desktop application developed with Java Swing and FlatLaf Light
features custom-painted Java2D components (such as an illuminated curved cinema
screen), real-time interactive seat grids, and a dual-tier client cache (L1 in-memory
LRU + L2 local disk cache) to virtually eliminate network bottlenecks. Both backend
and desktop clients employ dedicated `app.properties` files, allowing production
URL re-pointing and database credential adjustments without recompiling application
binaries. Rigorous integration testing validated zero-race-condition booking,
instant seat release upon cancellation, and smooth execution across environments.


3. PROBLEM STATEMENT
--------------------------------------------------------------------------------
Conventional and legacy ticket booking systems face several persistent issues:

1. Seat Contention and Double-Booking: High-concurrency screening events often suffer
   from race conditions where two or more customers select and pay for the same seat
   simultaneously, leading to transactional inconsistencies and customer dissatisfaction.
2. Network Latency & Image Rendering Overhead: Movie booking systems rely heavily on
   rich visual assets (posters, banners). Repeatedly fetching high-resolution images
   over high-latency network connections causes UI freezes, sluggish frame rates,
   and excessive server bandwidth consumption.
3. Decoupled and Fragmented Administration: Cinema operators often manage movies,
   auditoriums, and customer accounts across disparate systems, lacking real-time
   synchronization between box-office modifications and customer availability.
4. Rigid Client Configuration: Desktop clients often hardcode API endpoints or rely
   on complex XML configuration schemes, making deployment transitions from local
   development to staging or production error-prone and requiring complete code
   recompilations.
5. Inconsistent User Experience: Traditional Swing desktop UIs appear dated, lack
   proper DPI scaling, fail to take advantage of large modern displays, and do not
   provide clear spatial mapping of auditoriums (such as differentiating VIP from
   regular seating tiers).


4. OBJECTIVES
--------------------------------------------------------------------------------
The primary goals of the CineMagic project are:

- To architect and build a modular, secure, and scalable REST API backend using
  Spring Boot 3, Spring Data JPA, and Spring Security.
- To persist all application data—including high-resolution movie posters as binary
  LONGBLOB streams—within a centralized MySQL database, guaranteeing full ACID
  compliance and self-contained backups.
- To implement an aggressive multi-level caching strategy:
  * Backend in-memory caching via Caffeine for hot queries (active movies, showtimes).
  * HTTP transport caching via Cache-Control headers and ETag validation (HTTP 304).
  * Desktop client dual-tier caching (L1 RAM LRU cache + L2 persistent disk cache).
- To develop a modern Java Swing desktop application incorporating:
  * FlatLaf Light modern theme.
  * Default maximized window launch (`JFrame.MAXIMIZED_BOTH`).
  * Interactive cinema auditorium layout with custom curved screen visualization
    and real-time seat availability (Available, Selected, Booked).
- To provide an integrated Web Admin Portal for full cinema management:
  * Executive dashboard with revenue and booking analytics.
  * Direct binary poster file upload and movie cataloging.
  * Showtime scheduling with dynamic auditorium assignment.
  * Booking cancellation and customer account removal with cascading cleanup.
- To provide externalized configuration (`app.properties`) for both backend and
  app tiers, enabling zero-recompilation production deployment.
- To provide comprehensive developer and operational documentation for compiling,
  packaging, and executing all system modules.


5. ADVANTAGES
--------------------------------------------------------------------------------
- High Performance & Ultra-Low Latency:
  By pairing Caffeine in-memory caching on the server with an L1 memory and L2
  disk cache on the desktop client, repeated movie poster views load in 0 ms
  without generating outbound network traffic.
- Transactional Reliability:
  Spring Data JPA with database-level isolation guarantees that seat reservations
  are atomic. Attempting to book an already reserved seat immediately triggers an
  HTTP 409 Conflict, completely eliminating double-bookings.
- Self-Contained Database Architecture:
  Storing posters directly in MySQL as binary BLOBs ensures that database backups
  and migrations capture all media assets without needing synchronized external
  Amazon S3 buckets or local filesystem directory mappings.
- Native Modern Desktop Aesthetics:
  The Swing client uses FlatLaf Light to deliver clean typography, smooth button
  hover effects, rounded cards, vector-drawn seat icons, and automated high-DPI
  display adaptation.
- Zero-Recompile Production Reconfiguration:
  The desktop application automatically inspects its local execution directory for
  an external `app.properties` file before falling back to bundled resources,
  allowing system administrators to repoint the backend REST API URL instantly.
- Secure Role-Based Access Control:
  Stateless JWT tokens distinguish standard customers (`ROLE_USER`) from cinema
  managers (`ROLE_ADMIN`), ensuring sensitive endpoints (user deletion, showtime
  creation, financial stats) remain strictly guarded.
- Automated Data Seeding:
  On initial deployment, the backend automatically seeds sample auditoriums,
  seat matrices, movies, posters, and screening schedules, enabling immediate
  turnkey demonstration and testing.


6. DISADVANTAGES
--------------------------------------------------------------------------------
- Increased Database Storage Footprint:
  Storing high-resolution image posters directly as LONGBLOB binary data inside
  MySQL increases database table size and can prolong database dump/restore
  times compared to storing plain URL references.
- Platform JRE Dependency:
  As a Java Swing desktop application, client workstations require a compatible
  Java Runtime Environment (JRE/JDK 21 or later) installed, or the application
  must be bundled with a custom jlink runtime.
- Limited Mobile Form Factor Compatibility:
  While the Web Admin Dashboard is fully responsive across desktop and tablet
  browsers, the desktop customer booking client is built with Java Swing and
  cannot run natively on iOS or Android devices without a separate mobile frontend.
- Memory Consumption on Client:
  The desktop app maintains an L1 in-memory poster cache. While capped at 50
  images with an LRU eviction policy, systems with strictly limited RAM must
  tune cache limits accordingly.


7. CHALLENGES ENCOUNTERED & SOLUTIONS
--------------------------------------------------------------------------------
1. Challenge: Concurrency & Seat Double-Booking Race Conditions
   - Problem: In high-traffic scenarios, multiple clients could fetch the same
     available seat list simultaneously, select identical seats, and attempt
     checkout at the same moment.
   - Solution: Enforced database-level transactional boundaries (`@Transactional`)
     and created an explicit `BookingSeat` cross-reference entity with foreign key
     integrity. Before committing, the service layer queries existing reservations
     for the showtime within the active transaction; any detected conflict throws
     a custom `DuplicateBookingException` returning HTTP 409 Conflict.

2. Challenge: Binary Image Delivery Latency & UI Freezing
   - Problem: Fetching uncompressed binary BLOBs from MySQL across REST requests
     for every movie card rendered caused noticeable stuttering in the Swing UI.
   - Solution: Built a multi-tier caching pipeline:
     * Server: Caffeine caches binary arrays in RAM and sets `Cache-Control` and
       `ETag` headers on responses.
     * Transport: Implemented conditional HTTP HEAD / GET checks.
     * Client: Created `PosterCache.java` with an L1 memory cache (Java SoftReference
       LRU map) and an L2 persistent disk cache under `~/.cinemagic/cache/posters/`.
       Movie cards load posters asynchronously in background threads via `SwingWorker`.

3. Challenge: Zero-Recompilation Production Backend Redirection
   - Problem: Hardcoded URLs or classpath-only configurations prevent users from
     pointing compiled JAR files to remote production servers without rebuilding.
   - Solution: Enhanced `ApiClient.java` with a three-stage resolution hierarchy:
     1. Search for `./app.properties` in the working directory alongside the JAR.
     2. Fallback to `/app.properties` bundled in the JAR's classpath.
     3. Default to `http://localhost:8080/api` if no file exists.
     Trailing slashes are automatically sanitized, and timeout thresholds can be
     customized per deployment.

4. Challenge: Foreign Key Constraints on User Deletion
   - Problem: Deleting a user who has existing bookings caused foreign key constraint
     violations in MySQL (`fk_booking_user`).
   - Solution: Engineered a cascade deletion workflow in `UserService.java`. When an
     admin removes a user, all associated `Booking` records and their child
     `BookingSeat` entries are deleted in an isolated transaction before the user
     record is deleted. Administrative accounts are protected against accidental
     self-deletion.

5. Challenge: Modernizing Legacy Swing Component Styling
   - Problem: Default Java Swing look-and-feels (Metal, Nimbus) look outdated, lack
     proper padding, and render poorly on high-resolution screens.
   - Solution: Integrated FlatLaf Light, implemented anti-aliased Java2D rendering
     hints, custom-painted a curved illuminated cinema screen (`CurvedScreenPanel`),
     and configured `MainFrame` to launch in maximized window state
     (`JFrame.MAXIMIZED_BOTH`) with responsive `WrapLayout` card flow.


8. RESULT
--------------------------------------------------------------------------------
The CineMagic Movie Ticket Booking System was successfully built, packaged, and
comprehensively validated:

- Backend Compilation & Startup:
  The Spring Boot backend compiled cleanly across all 50 source classes and launched
  on port 8080, automatically creating the MySQL schema `movie_booking_db` and seeding
  initial administrator credentials, auditoriums, seats, and movie records with
  binary posters.
- Performance & Caching:
  Caffeine server-side caching and client-side `PosterCache` achieved sub-1ms
  render times for movie catalogs and poster thumbnails upon cache hits. ETag
  conditional requests correctly responded with HTTP 304 Not Modified.
- Admin Dashboard Functionality:
  The web dashboard at `http://localhost:8080/admin/` provided full operational
  management: secure JWT login, live revenue/booking charts, multipart poster
  file upload directly to MySQL `LONGBLOB`, showtime scheduling with seat price
  overrides, and permanent user removal with cascading booking cleanup.
- Desktop Client Execution:
  Packaged as a standalone shaded executable JAR (`movie-booking-app-1.0.0.jar`, ~4MB).
  The desktop application successfully launched in maximized state, connected to
  the backend, loaded catalog data, allowed customer registration and login,
  facilitated interactive seat selection with live price calculation, executed
  reservations, and allowed booking cancellations with immediate seat recovery.
- Production Portability:
  Verified that placing an external `app.properties` file in the application directory
  successfully overrode the backend REST target without modifying the packaged JAR.


9. CONCLUSION
--------------------------------------------------------------------------------
The CineMagic project demonstrates the successful fusion of enterprise-grade
Spring Boot backend engineering, relational database management, and modern
Java Swing desktop development. By treating performance and caching as first-class
concerns, the system overcomes traditional client-server bottlenecks, delivering
instantaneous visual feedback and robust data synchronization.

The centralized storage of binary media within MySQL, paired with Caffeine and
dual-tier client caching, provides a dependable, self-contained architecture
requiring minimal external infrastructure. Furthermore, the decoupling of
configuration via `app.properties` ensures operational readiness across local,
testing, and production environments.

Future iterations of CineMagic could expand upon this foundation by integrating
third-party payment gateway APIs (e.g., Stripe, PayPal), generating QR-code
tickets with automated turnstile scanner validation, and deploying a complementary
mobile client using modern cross-platform frameworks.
